# Test-only attested outbox producer

This producer is disabled unless `REVIEWS_ENVIRONMENT=test` and `REVIEWS_SOURCE_PRODUCER=test`. It needs private service bindings `SOURCE_API` and `REVIEWS_API`, `COMMERCE_DB`, an `EVENT_QUEUE` producer binding, a `CF_VERSION_METADATA` binding, and distinct secrets `CF_READ_TOKEN`, `SOURCE_IDENTITY_TOKEN`, `REVIEWS_ACTIVATION_TOKEN`, `TRIGGER_TOKEN`, and a 32-byte hex `SOURCE_EVENT_KEY`. Set the scoped Cloudflare account, Worker names, database ID, Stripe account ID, store, issuer, installation, catalogue version, exact Reviews mapping SHA-256, and numeric activation policy variables shown in `worker.mjs`. The read token needs only the control-plane read permissions for the three Workers. No email, recipient or Reviews collection binding is used.

Before each relay the producer checks current Cloudflare deployments and exact version settings for the source, producer and Reviews Workers. It rejects traffic splits, source/producer/Reviews D1 binding mismatches, wrong service binding targets, source identity, store, test mode, catalogue or exact mapping mismatches. The source identity endpoint uses the source Worker's own Stripe test credential to fetch the account and reports its own version metadata; this endpoint is authenticated and disabled unless `CARTRAY_REVIEWS_SOURCE=test` and a separate identity token are configured. The source Worker also needs a version metadata binding and private `REVIEWS_SOURCE_TRIGGER` service binding. Configure `CARTRAY_REVIEWS_PRODUCER=test` and matching trigger token only for a qualified test deployment.

The producer asks the existing idempotent activation endpoint for its primary-session no-backfill watermark. A dedicated immutable installation-scoped checkpoint is created at that watermark. At most 20 confirmed outbox IDs are enqueued per run, then the checkpoint advances by compare-and-set only after queue acceptance. A crash after send may duplicate a hint; the downstream Reviews transaction deduplicates it. The normal webhook wakes this producer asynchronously after settlement; the existing scheduled reconciliation wakes it for recovery. Neither missing bindings nor a failing wakeup change checkout responses. The source producer must also have a bounded scheduled trigger for backlog recovery.

This is an unqualified test implementation: configuration, Cloudflare control-plane credentials, resource bindings, topology, version changes, timeouts and end-to-end behavior must be validated under Workerd and hosted sandbox before enabling it. A control-plane check cannot make a deployment change and an in-flight send atomic; deployment changes must quiesce and revalidate this source before new events are accepted. Production, arbitrary backfill and outgoing invitations remain disabled.
