# Stalled-upload transport reproducer

Run `modules/reviews/tests/stream_repro/run-linux.sh` from this checkout. It uses Docker, Node 24.20.0 and this repository's npm lockfile (Wrangler 4.127.1 and Workerd 2026-08-28). It runs otherwise equivalent minimal JavaScript and Python handlers, each through a direct Workerd listener and Wrangler's local proxy. No D1 or Reviews business logic is involved.

The probe reports the completed malformed request, a health request during an incomplete upload, the stalled socket's outcome, and ten subsequent health probes. Handler logs distinguish application return from on-wire delivery. A timeout, reset or listener failure is a transport outcome, not an application 400. This reproducer is diagnostic: it reports behavior rather than hiding a proxy failure. It does not qualify the deployed Cloudflare runtime.

Observed on Linux with the pinned versions: both direct listeners returned HTTP 400 for a stalled upload and passed ten health probes after the client closed. Both proxy listeners returned 400 for a completed body and served health checks during the stall, but the incomplete socket timed out; after the client closed, one health request succeeded and later requests were refused. Both languages reproduced this with no D1. This isolates the local proxy path, but does not explain its internal crash. The original Reviews proxy diagnostic can be run with `REVIEWS_PROXY_STALL_DIAGNOSTIC=1`; it remains outside the normal lifecycle gate because of this reproducible tooling failure. `direct_gate.py` is mandatory in CI, while the ordinary Reviews Workerd/D1 lifecycle test remains mandatory.

The disposable hosted Reviews test and its limitations are recorded in [the locked receipt](hosted-receipt-2026-11-05-locked.json). To repeat the HTTP portion against a separately provisioned disposable Worker, run `uv run python modules/reviews/tests/stream_repro/hosted_probe.py HOST SECRET_FILE`; this does not create or delete resources or compare D1 rows. Provisioning, row comparisons and teardown are still manual.

Related upstream reports discuss proxy disconnects and exits: [workers-sdk #15203](https://github.com/cloudflare/workers-sdk/issues/15203) and [workers-sdk #15451](https://github.com/cloudflare/workers-sdk/issues/15451). They are consistent with the local observation; they do not establish that every failure has the same cause.
