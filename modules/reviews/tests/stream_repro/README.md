# Stalled-upload transport reproducer

Run `modules/reviews/tests/stream_repro/run-linux.sh` from this checkout. It uses Docker, Node 24.20.0 and this repository's npm lockfile (Wrangler 4.127.1 and Workerd 2026-08-28). It runs otherwise equivalent minimal JavaScript and Python handlers, each through a direct Workerd listener and Wrangler's local proxy. No D1 or Reviews business logic is involved.

The probe reports the completed malformed request, a health request during an incomplete upload, the stalled socket's outcome, and ten subsequent health probes. Handler logs distinguish application return from on-wire delivery. A timeout, reset or listener failure is a transport outcome, not an application 400. This reproducer is diagnostic: it reports behavior rather than hiding a proxy failure. It does not qualify the deployed Cloudflare runtime.

Observed on Linux with the pinned versions: both direct listeners returned HTTP 400 for a stalled upload and passed ten health probes after the client closed. Both proxy listeners returned 400 for a completed body and served health checks during the stall, but the incomplete socket timed out; after the client closed, one health request succeeded and later requests were refused. Both languages reproduced this with no D1. This isolates the local proxy path, but does not explain its internal crash or prove production behavior. The Reviews Workerd/D1 test remains a separate, failing qualification gate.

Related upstream reports describe a Wrangler proxy exit after a client disconnects during upload: [workers-sdk #15203](https://github.com/cloudflare/workers-sdk/issues/15203) and [workers-sdk #15451](https://github.com/cloudflare/workers-sdk/issues/15451), the latter reporting Wrangler 4.127.1. They are consistent with the local observation; they do not establish that every failure has the same cause.
