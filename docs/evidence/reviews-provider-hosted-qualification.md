# Reviews SMTP2GO provider lookup: hosted synthetic qualification

On 2026-11-07 UTC, a disposable test-only Worker ran the provider-reconciliation adapter in the existing personal Cloudflare account. It used the isolated Acorn Reviews D1, not commerce or purchaser-context D1. The adapter had no public route; a separate, temporary bearer-protected probe called it through a private Worker service binding. Both disposable Workers were deleted after the test. No email was sent.

The three reviewed additive migrations 0030, 0031 and 0032 were applied in order to that test database. Beforehand, a private mode-600 SQL export was made; its SHA-256 was `1f55c1b7e1a1f288ea610c58ccfa49792e2504ebfc806e6ae7cac5c5c20a9014`. The synthetic sender's active configuration was `INITIAL_SEND_MODE=disabled`, and the scheduler's was `REVIEWS_DUE_SCHEDULER=disabled`. Their test-only configurations were not changed during this exercise.

An existing accepted synthetic invitation was correlated to one SMTP2GO email by the exact delivery-identity custom header in a complete, bounded read-only provider activity search. Its already-recorded acceptance time and correlated provider identity were inserted into the new provider receipt table. Two authenticated hosted calls returned `observed` with `processed` and `delivered` events. After both calls, D1 contained exactly one observation of each type, one provider identity, and the original generation remained accepted. A probe request without the correct bearer returned HTTP 404. Provider acceptance and final delivery remain separate outcomes.

The source file uploaded to the private adapter had SHA-256 `fdcd617f3f9b334a6fb95c5b10a16b86db2663e357750e4e6f1654f72ef0535c`, matching the adapter file at the tested branch head. Cloudflare reported active Worker version `2aaeffe6-b754-4e1f-a17e-7cf2e7862adc` at 100%, with the expected test environment, D1 and secret binding names. Its reported script ETag was `feecf2e2ed959250dc2b544d8a0bcd54843b9a08f74b34e08e87082b988e37fa`; that ETag is not a verified hash of the source file. Remote source-byte parity was not independently established.

This qualifies the hosted observed/replay path for one synthetic SMTP2GO message. It does not qualify hosted staff authentication, the discovery path, bounce/rejection/unknown outcomes, provider outages, or a production sender. Those cases have separate local tests or remain release gates. The backup is private because it can contain synthetic recipient and capability data; its contents are not part of this receipt.
